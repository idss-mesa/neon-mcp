# Agent guide — neon-mcp

This repository holds **neon-mcp**, a [Model Context Protocol](https://modelcontextprotocol.io/)
server (MCP 2026-07-28, stateless core) for the NEON Data API, and its
documentation site, https://idss-mesa.github.io/neon-mcp/. The server is
Python 3.11+ on the `mcp` 2.x SDK: package `neon_mcp` under `src/`, console
script `neon-mcp`, tests under `tests/`. The site is built with
[Zensical](https://zensical.org) from `docs/`, which is an **Open Knowledge
Format (OKF) v0.2 knowledge bundle**
([spec](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md)):
every content page carries YAML frontmatter with `type` (Guide | Tutorial |
Reference | Policy | MCP Tool Reference), `title`, `description`, `tags`,
provenance (`generated`, `sources`) and lifecycle (`status`, `stale_after`)
fields. Section `index.md` files are OKF §8 directory listings (no
frontmatter); `docs/log.md` is the OKF §9 dated change log.

## Reading the corpus

- `docs/llms.txt` — linked outline of every page with descriptions.
- `docs/llms-full.txt` — the entire corpus in one file, frontmatter included.
- Live site: any page URL + `index.md` returns that page's Markdown source
  (e.g. https://idss-mesa.github.io/neon-mcp/getting-started/api-token/index.md);
  `robots.txt`, `sitemap.xml`, `llms.txt` and `llms-full.txt` sit at the site
  root; the agent guide is at `/about/ai-agents/`.
- Trust: pages without a `verified:` key are **unverified** (OKF §5.3);
  `status: deprecated` pages are history, `status: draft` pages need review.
  Pages with `stale_after` state facts NEON or MCP may change (rate limits,
  token rules, release tags, SDK versions) — re-check them after that date.
- For NEON *data*, do not read the docs: run the server and call its tools.

## Commands

```bash
# Server
uv sync                                       # install the package + dev extras into .venv
uv run pytest                                 # unit tests (recorded fixtures; no network)
uv run ruff check . && uv run ruff format --check .
uv run neon-mcp --transport stdio             # run the server locally

# Documentation
pip install zensical pyyaml
zensical serve                                # live preview at localhost:8000
zensical build --clean --strict               # static site -> site/ (must print "No issues found")
python scripts/okf_validate.py docs           # OKF conformance (CI-enforced; 0 errors required)
python scripts/gen_llms_txt.py                # regenerate docs/llms.txt + docs/llms-full.txt (CI checks drift)
python scripts/postbuild_agent_surface.py site  # after build: md mirror + okf:* meta + robots.txt
```

The three docs scripts need only PyYAML; they never import the package.

## Editing rules

1. **Every content page** under `docs/` starts with OKF frontmatter: a
   non-empty `type`, plus `title`, `description` (one plain sentence, 50–160
   characters — it becomes the meta description and the `llms.txt` entry),
   `tags`, `generated: { by, at }` and `sources` (each with `id`, `resource`,
   `title`, `author`). Add `status` and `stale_after` when the page states
   facts that may change. Run `okf_validate.py` before committing — CI fails
   otherwise.
2. **`index.md` files carry no frontmatter.** A section index is a
   `# Heading` followed by `* [Title](page.md) - description` bullets listing
   every page in that directory. The one exception is the root
   `docs/index.md`, which carries only `okf_version: "0.2"`, `title` and
   `description`.
3. **`docs/log.md`** gets a dated entry (`## YYYY-MM-DD`, newest first;
   `* **Creation**:` / `* **Update**:` / `* **Deprecation**:`) for every
   substantive documentation change.
4. **Regenerate after content changes:** `python scripts/gen_llms_txt.py`,
   then commit `docs/llms.txt` and `docs/llms-full.txt` with the change. The
   tool reference `docs/tools/reference.md` is generated by
   `scripts/gen_tools_reference.py` (phase 2) — never hand-edit it.
5. **New pages go in the `nav` array of `zensical.toml`** (and in their
   section's `index.md`); `zensical build --strict` must still report
   "No issues found".
6. **Links:** internal links are relative and plain (`api-token.md`,
   `../about/license.md`); external links get `{target=_blank}`. Code
   belongs in fenced blocks with a language. Images live under
   `docs/assets/` and are referenced by relative path.
7. **Actors** (OKF §7): `generated.by` is `<producer>/<version>` for an
   agent or tool (e.g. `claude/fable-5.1`), `human:<id>` for a person,
   `process:<id>` for an automated job. Bump `generated.at` on a meaningful
   content change.
8. **Never add `verified:`.** Only a human maintainer does that, as
   `verified: { by: "human:<id>", at: <ISO 8601> }`.
9. Do not name or enumerate tools in prose beyond what the generated tool
   reference documents; link to the reference instead so the docs cannot
   drift from the registry.
